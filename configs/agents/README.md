# Complete Agent configurations

Each YAML freezes a model ID, a harness implementation/version, temperature, token cap and model-turn cap. Compare a model matrix under one harness or a harness matrix under one model; do not describe a mixed matrix as a pure model comparison.

The implemented harnesses are AISLE's own `json` and `tools` adapters using an OpenAI-compatible Chat Completions API. `json` requires `{"action": ...}` or `{"finish": true}`. `tools` exposes one native `submit_experiment` function and permits `{"finish": true}` when finished. Format and action-validation errors feed back to the Agent within `max_turns`. These are not implementations of Codex CLI, Claude Code, or arbitrary external complete agents. `skills` is currently required to be empty and fails explicitly otherwise. Provider options such as `extra_body: {enable_thinking: false}` are explicit frozen configuration; they cannot override model, messages, tool definitions, temperature, token limits or streaming mode.

Set model credentials as environment variables named by `base_url_env` / `api_key_env`. Keep values outside YAML and Git. Base URL may be the API root ending in `/v1` or the full `/chat/completions` endpoint. `token_parameter` selects `max_tokens` (default) or `max_completion_tokens` for providers that require the latter; the numeric cap remains `max_tokens` in the configuration. Raw model responses supply token usage. `model_calls` counts received responses, `model_request_attempts` counts forwarded requests, `usage_missing_calls` counts responses without usage, and `usage_unknown_calls` counts interrupted requests whose provider consumption is unknown. Unknown usage must never be read as zero consumption. No price assumptions or fabricated dollar costs are made.

`local` executes the same worker in the controller process for development. It is not a sandbox boundary against untrusted third-party code. `tencent` creates a Tencent Agent Sandbox, uploads only the stdlib worker and public task/Agent state, and exchanges one step at a time through files/commands RPC. The simulator and scorer remain controller-side; no inbound controller HTTP access is required. The worker constructs the complete model request. A controller-side transport forwards it unchanged and returns the model response to the worker for interpretation. Model credentials never enter the Sandbox. This avoids reliance on Sandbox outbound access to model endpoints; the controller must have that access. No credential value is written to trajectories or console logs.

The controller stores the exact request and response as content-addressed evidence. A response is persisted before the Sandbox parses it, so a phase-two RPC failure can resume without another model API call. The model endpoint is bound at first execution; changing it during resume is rejected. The controller writes its checkpoint and stable proposal key before submitting an experiment. `waiting_for_lab` ends the active continuation and destroys the sandbox; a later continuation restores the externally persisted conversation, pending work and budget. The SQLite ledger and process locks assume one controller host in this MVP. Distributed controllers would require a shared lease mechanism.

Tencent settings can be provided via `TENCENT_SANDBOX_API_KEY`, `TENCENT_SANDBOX_DOMAIN`, and `TENCENT_SANDBOX_TEMPLATE`, or `~/.config/aisle/sandbox.json` with mode `0600`. Environment values override file settings. The adapter records sandbox ID, template, domain, SDK version, worker source hash and harness fingerprint. `scripted` is exclusively an engineering smoke agent and is excluded from official Top-K selection.
