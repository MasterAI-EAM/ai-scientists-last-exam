# AISLE 新框架图

三页中文框架图，解释同一个任务如何先通过仿真筛选，再由真实湿实验检验完整 Agent。图中包含目标流程与正式验收要求，不代表所有实验室已通过验收或每个接口已完成生产验证。

| 文件 | 内容 |
|---|---|
| `aisle_framework.drawio` | 三页可编辑源文件，模块、文字和连线均为原生 draw.io 元素 |
| `01-framework.png` / `.svg` | 统一任务约定 → 完整 Agent → 全部参加仿真 → Top-K → 真实湿实验 → 反馈 |
| `02-contribution.png` / `.svg` | 合作实验室需要提供的材料，以及仿真、真实实验准备两项验收 |

## 设计依据

本版按用户给出的 `fig1_introduction_drawio_v19.drawio` 重新组织视觉：白底、柔和分区色、深灰虚线分组、简短中文、图标与原始实验设备照片，以及清楚的动作—观测—反馈主线。中文采用 PingFang SC；色相参考原图，部分文字颜色略加深以提高可读性。不是给旧英文框图逐字换标签。

参考图中的文档、机器人图标和苏州实验室设备照片按原始字节提取并复用。没有重新生成、修饰、裁剪或替换设备照片；`assets/provenance.json` 记录来源节点和 SHA-256。原参考文件没有修改。照片和图标属于图内素材，其他结构仍可分别编辑。

## 保留的科学与流程约束

- 每项任务必须同时能构建仿真、能开展真实湿实验；任务目标、动作、观测、约束、预算及科学指标需要明确。
- 比较完整 Agent：模型、运行框架（harness）、工具与记忆。腾讯云沙箱承载 Agent 的计算和工作区。
- 全部参评 Agent 先做仿真，只有提前固定规则下的 Top-K 进入正式真实评测。
- 人主要执行标准操作、测量和回传事实；科研方案修改需要记录并单独标明人类辅助。
- 工单和实验编号持续保存；重复提交、执行状态不明、质控失败不能触发不受控的重复湿实验。
- 原始数据、评分依据、版本与资源账本完整保留。任务开发中的参考、校准、质控工作与参评 Agent 实验分开记账。
- 配色示例展示 200 µL 非负整数配方、CIEDE2000 优化指标及禁区约束；该约束是评测代理，不代替实验室真实安全规范。

## 重建与导出

仅重建可编辑 XML：

```bash
python3 docs/diagrams/build_diagrams.py
```

使用 draw.io Desktop CLI 一次导出三张 PNG、三个 SVG 和三页 PDF：

```bash
python3 docs/diagrams/render_diagrams.py
```

必要时明确指定 CLI：

```bash
python3 docs/diagrams/render_diagrams.py \
  --drawio /Applications/draw.io.app/Contents/MacOS/draw.io
```

PNG 是用于阅读和检查的非嵌入导出；SVG/PDF 保留源图。所有原始素材已在 `assets/` 中，重建不依赖用户机器上的原参考文件。
