# 配色任务：一份完整的 sim 验收交付样例

本样例解释实验室怎样交付、平台怎样判定。**当前真实验收结论仍是 pending；下文带数值的结果表是教学算例，不是现有 LightGBM 的独立实测成绩。** 正式结果见 [sim-validation-report.json](sim-validation-report.json)，其中未测值全部为 null。

## A. 任务与文件

| 项目 | 本例固定内容 |
|---|---|
| 科学操作 | Red/Green/Blue/water 为非负整数 μL，总量200 μL |
| 科学目标 | 接近目标 `test_74`，CIE Lab `[72.41,-71.63,32.26]` |
| 成功 | 到目标的 CIEDE2000 距离≤2.0，不在比较前取整 |
| 预算 | Agent 每次运行12轮、最多12个实验样品；验证集建设另计预算 |
| 预测对象 | 同一配方在冻结 SOP/测量条件下的 CIE Lab |
| simulator | 固定 LightGBM 资产，SHA-256 `a52a7bb3c6af4f1807a285ef891ff7aff8021f1dd4df56af35fe9fc16ce24819` |
| 验收 profile | `aisle-color-sim-v0.1`；全部数值门槛见计划JSON |
| 安全扩展 | 中心同目标，禁止距离闭区间[1.5,3.0]；使用独立的 safety profile |

任务包内交付：

```text
task.yaml / SOP.md / scoring.md / acceptance.md
validation/
  README.md                         # 本样例与指标口径
  sim-validation-plan.json          # 明确阈值、采样/统计计划、冻结签署

```

实验室另交受控数据包，不直接提交私有数据到 Git：训练/开发/最终测试清单，原始仪器输出、配方与样品映射，校准/QC记录，指标计算程序与环境锁文件，以及每份材料的 URI、SHA-256、权限、负责人。现有 PSI-Bench 训练 CSV 不能改名当作独立 holdout。

## B. 在看最终结果前冻结

1. 补全 SOP 中材料批号、设备、观察条件、读数聚合方式、QC阈值与异常处理。验证和正式任务使用同一聚合方法；人执行固定配方并返回测量。
2. 先在独立的开发/QC阶段确认实验噪声与动作可行域，确定哪些配方附近需要加密。冻结模型、预处理、目标、评分实现与计划。
3. 登记300个以上不同配方，每个用一个独立制样单元作为主验证记录；至少3个新实验批次、3天。普通动作域样本≥100，高分区≥60，成功边界≥60且两侧各≥30；真实成功/失败各≥60，预测成功≥30。
4. 冻结配方采样清单、种子20261102、样品执行顺序随机化规则、最大尝试数与补覆盖规则。高分/边界的最终分层按**真实测量**确定；若实际覆盖不足，记录证据不足，不能因误差不好而挑掉某些配方。开发集可帮助预选边界候选，但不能混进最终测试。
5. 选其中至少30个配方，每个共3次独立制样，跨至少3批次评估噪声。若首个制样已计入主验证，新增至少60个制样，因此这个最小方案至少360个物理样品，另加校准/空白/QC。重复读数不能把独立配方数300变成900。
6. 两位科学责任人填写身份和日期，冻结采样清单/协议哈希；`status` 改为 `frozen`。任何计划内容修改都要重新计算报告中的 `plan_sha256`。当前模板尚未填写全部实验信息，状态是 `proposed`。

如果同一份数据同时验证安全变体，还须保证1.5和3.0各自±0.25区间各≥60，内外两侧各≥30，真实违规/允许各≥60。两个profile分别出报告，不额外宣称独立重复了一份实验。

## C. 数据表怎样交

每行代表一次独立制样；同一样品的技术读数保留在原始文件中。至少提供：

```csv
sample_id,recipe_id,batch_id,prepared_at,split,Red,Green,Blue,water,real_L,real_a,real_b,sim_L,sim_a,sim_b,qc_status,raw_uri,raw_sha256,sop_sha256,simulator_sha256
```

`split` 标明 train/development/final_test/noise_repeat；重复配方通过 `recipe_id` 关联但 `sample_id` 不重复。原始证据里还需记录实际执行量、仪器/材料版本、读数聚合、操作员与偏差。预测应由审核者用冻结模型从配方重算；不能直接相信贡献者手填的 `sim_L/a/b`，也不能只提供最终误差表。保留 QC 失败/缺失/域外请求，逐项解释；缺失的真实 Lab 不按零填充。

## D. 从配方到指标

对每条主验证记录计算：

```text
e = DeltaE00(sim_Lab, real_Lab)          # simulator 颜色保真度
d_real = DeltaE00(real_Lab, target_Lab) # 真实任务分数
d_sim  = DeltaE00(sim_Lab, target_Lab)  # 模拟任务分数
delta = d_sim - d_real
real_success = (d_real <= 2)
sim_success  = (d_sim <= 2)
```

先按固定 QC/分层规则形成总体、各批次、高分区和边界区，分别统计。逐通道 MAE/RMSE/R² 和偏差必须填写；主判定使用 e 的均值/P95、delta 的 RMSE、距离排序及成功/违规误判。完整公式、分母和门槛见 [sim verifier 规范](../../../../docs/sim-verifier-acceptance.zh-CN.md)。

例如某个样品 `d_sim=1.2` 而 `d_real=2.2`，就是一次**成功假阳性 FP**。即使模型整体 R²=0.99，这次误判仍计入 FP，不会被 R² 抵消。

正式报告还必须附**全部分层统计和95%区间**、技术读数噪声、缺失/OOD记录与证据哈希。教学表未生成原始数据或区间，不能因此判定 G2 通过。

成功混淆矩阵（真实成功为正类）：

| 真实结果 | sim成功 | sim失败 | 合计 |
|---|---|---|---|
| 成功 | TP=75 | FN=5 | 80 |
| 失败 | FP=3 | TN=217 | 220 |
| 合计 | 78 | 222 | 300 |

- 总体判定不一致率：`(3+5)/300=2.67% ≤5%`。
- 假设成功边界90个样品里有5次不一致：`5/90=5.56% ≤10%`。
- 成功假阳性率：`3/220=1.36%`；单侧95%上界 **3.4865%≤5%**。
- 预测成功中的错误占比：`3/78=3.85%`；单侧95%上界 **9.6413%≤10%**。

安全扩展教学算例：真实违规120个，其中1个被sim错误判为允许；真实允许180个，其中8个被错误判违规。则假安全率 `1/120=0.83%`，上界 **3.8921%≤5%**；假违规率 `8/180=4.44%`，上界 **7.8762%≤15%**，两者点估计也达标。两个边界区各60个、每区真实违规30个，假设边界漏检分别为0和1，则分层假安全率为0%和3.33%，均≤5%；仍须分别验收边界色差均值/P95。假设其均值为0.22、0.25，P95为0.44、0.48，则这两项达标。

上界可在仓库环境复算（SciPy 已在项目锁定的依赖环境中）：

```bash
uv run python - <<'PY'
from scipy.stats import beta
for errors, denominator in [(3, 220), (3, 78), (1, 120), (8, 180), (0, 60), (2, 100)]:
    upper = 1.0 if errors == denominator else beta.ppf(0.95, errors + 1, denominator - errors)
    print(errors, denominator, f"U95={upper:.4%}")
PY
```

反例：假安全错误2次/真实违规100个，点估计恰为2%，但单侧上界6.1619%超过5%，**不通过**。只有20个真实违规样本即使0次漏检，也不足以通过本 profile 的样本量与上界门槛。

## F. 如何出最终审核结论

1. **G1 工程合并**：计划与报告齐全、数值门槛明确、代码/接口测试通过；允许以 draft 合并，但不授予正式评测资格。
2. **G2 数值审核**：按冻结程序重算各指标，报告逐项 `pass/fail/insufficient_evidence`；任何硬指标失败不能由其他好指标补偿。统计假设不成立时即使点估计漂亮也只能记证据不足。
3. **G2 科学签署**：独立审核者核对实际数据、盲测/划分/批次独立性、噪声、覆盖范围和全部原始证据；签署版本和适用条件。报告 `accepted` 不能只有贡献者自行勾选。
4. **正式用途**：G2及真实实验室G3同时通过，才可将本任务正式sim成绩用于Top-K筛选；真实Agent仍由入选系统提出方案，人执行并回传新鲜测量。

本仓库当前 `sim-validation-report.json` 的合法结论是：**未提供独立真实 holdout，G2 pending；此处只交付完整的计划、报告格式和验收方法。** 工程测试与教学算例不改变这一状态。

在仓库根目录执行 `uv run python scripts/validate_contributions.py` 可检查材料是否齐全及内部一致；它不会计算上述科学指标，也不会验证原始实验是否真实。`plan_sha256` 使用计划文件的原始字节 SHA-256，更新后可用 `shasum -a 256 examples/tasks/color_matching/validation/sim-validation-plan.json` 取得实际值并填入报告。
